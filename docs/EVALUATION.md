# Evaluation methodology

The synthetic-v1 benchmark has 24 independently authored startup/partner labels: nine valid, fourteen invalid and one ambiguous. It is a regression fixture, not a representative sample of the energy market. Labels live in backend/app/domain.py and are not generated by the matcher.

For each innovator, select at most K eligible partners in descending score order, ties by partner ID. Rejected and review candidates never enter recommendations.

| Metric | Numerator | Denominator |
|---|---|---|
| Precision@K (returned convention) | Returned pairs labeled valid | All returned pairs, up to K per innovator |
| Recall@K | Returned pairs labeled valid | All nine valid labeled pairs |
| Hard-rule violation rate | Returned pairs with a failed hard rule | All returned pairs |
| Evidence coverage | Sum of per-innovator fractions of six factors represented | Number of innovators |
| Data freshness | Records whose verification or observation age is 0–180 days | All source records |
| Unknown handling | Ambiguous pairs correctly routed to review | Ambiguous pairs (one) |

Undefined precision/recall/violation denominators return null, not invented zero. Ambiguous labels are not positive relevance labels. At AS_OF_DATE=2026-10-14 and K=2, the fixed fixture returns 9/9 valid pairs, precision 1, recall 1 and zero hard violations. K=1 returns 5/9 relevant pairs (55.6% recall). Coverage is 29 of 36 factor slots (~80.56%; UI averages rounded per-record values to 80.5%). There are 30 evidence records. Scores are heuristic ranking indices, never probabilities.

Regression counts mismatches between all current pair statuses and expected valid→eligible, invalid→rejected, ambiguous→review labels. Changing K affects recommendation metrics but not expected rule labels. Evidence ages change with the evaluation date; record it with every result. The UI displays date, K, version, denominators and all labeled pairs.

Tests cover incorrect eligibility, unknown stages, cosine behavior including zero vectors, evidence missingness, conflicts, freshness boundaries, no-mutation scenarios, metrics, malformed API inputs and Cloudflare timeout/grounding fallback. Live provider connectivity is a separate integration check and is not implied by mocked tests.
